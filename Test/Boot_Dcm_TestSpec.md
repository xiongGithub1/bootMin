# Boot DCM（表驱动 UDS）测试用例规格书

目标：全面验证 `autosarTc364_Boot (2)` 的 UDS/DCM 实现，覆盖
会话切换、SecurityAccess 解锁、服务权限矩阵、P2/P2*/S3 超时、
负向应答码、刷写全流程和异常路径。

## 1. 测试环境

| 项目 | 值 | 来源 |
|---|---|---|
| 诊断物理请求 ID | `0x74C` | `CanIf_RxPduConfig` / `CddPduRUpperLayerRxPdu_74c` |
| 功能请求 ID | `0x7DF` | `msg_diag_RequestGlobal_Tp` |
| 诊断应答 ID | `0x75C` | `CanIf_TxPduConfig` / `CddPduRUpperLayerTxPdu_75c` |
| CAN 波特率 | 500 kbit/s | `Can_InitObjectBaudrate = 500u` |
| P2 / P2* | 50 ms / 5000 ms | `Boot_Dcm_Cfg.h`（0x10 应答字节 `00 05 / 01 F4`） |
| S3 | 5000 ms | `Boot_Dcm_Cfg.h` |

硬件：PCAN-USB / Vector 等任意 CAN 卡 + 终端电阻；boot 运行在目标板上，
需能上电并进入诊断（CAN 通信已启动）。

## 2. 预期权限矩阵（与 `Boot_Dcm_SvcTable[]` 一致）

会话：D=默认(0x01)，P=编程(0x02)，E=扩展(0x03)；安全：L=未解锁，L1/L3=已解锁。

| SID | 服务 | D | P | E | 需要解锁 |
|---|---|---|---|---|---|
| 0x10 | DiagnosticSessionControl | 允许 | 允许 | 允许 | 无 |
| 0x11 | ECUReset | 允许 | 允许 | 允许 | 无 |
| 0x22 | ReadDataByIdentifier | 允许 | 允许 | 允许 | 无 |
| 0x27 | SecurityAccess | 0x7F | 允许 | 允许 | 无 |
| 0x2E | WriteDataByIdentifier | 0x7F | 允许 | 允许 | L1 |
| 0x31 | RoutineControl | 0x7F | 允许 | 允许 | L1 |
| 0x34 | RequestDownload | 0x7F | 允许 | 0x7F | L1 |
| 0x36 | TransferData | 0x7F | 允许 | 0x7F | L1 |
| 0x37 | RequestTransferExit | 0x7F | 允许 | 0x7F | L1 |
| 0x3E | TesterPresent | 允许 | 允许 | 允许 | 无 |

> 说明：0x27 在默认会话直接回 `0x7F`（SNSIAS）；0x2E/0x31 未解锁回 `0x33`（SAD）；
> 0x34/0x36/0x37 在扩展会话回 `0x7F`。其余子功能/长度/参数错误由各处理器回
> `0x12/0x13/0x24/0x31/0x73` 等。0x22 服务本身三会话都允许，**DID 另有会话隔离**（见下表）。
> 安全解锁按会话分开：`UnlockExt` / `UnlockProg` 互不拷贝；`10 01` / S3 回默认时两边都清。

### DID 会话（`Boot_Uds_DidReadMask` / `DidWriteMask`）

错会话读/写业务 DID 回 `0x31`（ROOR），不是 `0x7F`。

| DID | 读 | 写 | 备注 |
|---|---|---|---|
| F180 | D/P/E | P/E（需 L1） | Boot 标识；回默认时复位为 `01 42 4F 4F 54` |
| F187 / F189 / F18C / F190 / F193 | **仅 E** | **仅 E**（需 L1） | 业务 DID，默认/编程 `22` → `7F 22 31` |
| F198 | 不可读（`0x31`） | P/E（需 L1） | fingerprint |

### H. CanTp 发送串行（默认执行，验证 TX busy/retry）

DaVinci CanTp 通道是 **FULL_DUPLEX**：允许同时收+发，但 **同一条 Tx N-PDU（`0x75C`）上一次 `Transmit` 未确认前不能再发**。旧 Boot 在 `PduR_CddTransmit==E_NOT_OK` 时丢掉 `50 02`。根因、三条丢应答路径和固件排队见 [Boot_CANoe_CAPL测试问题总结.md](../bootNote/Boot_CANoe_CAPL测试问题总结.md) 第 5、11 节。下列用例把 tester 间隔设为 **0 ms**（普通用例仍保留 20 ms），用来验证 `Cdd_TpTxBusy` / retry / `Cdd_RxDeferred`。

| ID | 前置 | 步骤 | 预期 |
|---|---|---|---|
| H1 | 默认 | 连续 `10 01`→`10 02`→`10 03`→`10 01`，应答到立刻发下一帧 | 四条都是 `50 xx 00 05 01 F4`（不得丢 `50 02`） |
| H2 | 默认 | 连续 8 次 `22 F180`，间隔 0 | 8 次 `62 F180 ...` |
| H3 | 扩展 | `22 F190`（ECU 多帧 TX）立刻 `22 F180` 立刻 `10 02` | `62 F190` / `62 F180` / `50 02`（多帧 TX 不得冲掉下一条应答） |
| H4 | 默认 | `10 02` 立刻发 11 字节 `34`（tester 多帧 RX） | `50 02` 后 `7F 34 33`（未解锁；FC 不得漏） |
| H5 | 默认 | 功能寻址 `3E 00` 立刻物理 `22 F180` | `7E 00` 后 `62 F180` |

### E. 刷写全流程、访问顺序与异常（破坏性，需先擦除 APP）

合法顺序（`Boot_Uds_Sm`）：

```text
10 02 → 27 L1 解锁 → 31 01 FF00 擦除 → 34 RequestDownload
      → 36 TransferData（BSC 从 1 递增，写满 size）→ 37 TransferExit
      → 31 01 FF02 CheckMemory → 31 01 FF01 CheckDependency
```

乱序时：未 `34` 的 `36`/`37` → `0x24` RSE；下载中再 `34`/擦除/`FF02` → `0x22` CNC；`37` 后未再擦除就 `34` → `0x22`；`FF01` 会把状态打到 CHECKED，之后 `FF02` → `0x22`。

| ID | 前置 | 步骤 | 预期 |
|---|---|---|---|
| E1 | 默认 | `10 02`→解锁→`31 01 FF00`（擦除）→`34 00 44 80 02 00 00 00 00 00 20`→`36 01`+32B→`37` | `50 02 00 05 01 F4` / `67 02` / `71 01 FF00` / `74 20 02 00` / `76 01` / `77` |
| E2 | E1 的 RD 之后 | `36 02`+数据（块计数器错误） | `7F 36 73`（WBSC） |
| E3 | RD(size=32) 之后 | `36 01`+超量数据 | `7F 36 31`（ROOR） |
| E4 | RD 之后 | `36 01`+非 32 对齐长度 | `7F 36 31` |
| E5 | P+L1 | `34 00 44 80 00 00 00 00 00 00 20`（boot 区地址） | `7F 34 31` |
| E6 | P+L1 | `34 00 44 80 04 00 01 00 00 00 20`（非 32 对齐） | `7F 34 31` |
| E7 | RD 之后未发完数据 | `37` | `7F 37 22`（CNC） |
| E8 | RD 之后 | `10 01`→`10 02`→`36 01`+数据 | `7F 36 33`（切会话后安全锁定、状态复位） |
| E9 | P+L1 | `31 01 FF00`+错误长度 | `7F 31 13` |
| E10 | E1 完成后（状态 PROGRAMMED） | `31 01 FF02`（CheckMemory） | `71 01 FF02` |
| E11 | E10 之后 | `31 01 FF01`（CheckDependency） | `71 01 FF01 00` |
| E12 | P+L1 已擦除 | `34 01 44` + APP 地址/长度 | `7F 34 31`（dataFormatIdentifier ≠ 0x00） |
| E13 | P+L1 已擦除 | `34 00 22` + 2B 地址 + 2B 长度 | `7F 34 13`（ALFID 必须 0x44，总长 11） |
| E14 | 已擦除 | `36` / `37` / `31 FF02` / `31 FF01` 再 `34` | `7F 36 24` / `7F 37 24` / `7F 31 22`，然后 `74` 仍成功 |
| E15 | 已擦除且已 `34` | 再 `34`；下载中 `31 FF00` / `31 FF02`；再 `36` | `7F 34 22` / `7F 31 22`，然后 `76 01` 仍成功 |
| E16 | 已擦除后 `34+36+37` | 再 `36`/`37`/`34`；先 `FF01` 再 `FF02`；再擦除后 `34` | `7F 36 24` / `7F 37 24` / `7F 34 22`；`71 FF01`；`7F 31 22`；再擦除后 `74` |
| E18 | 已擦除且已 `34` | `10 03` 再 `36` | `7F 10 22`（下载中禁止进扩展）；随后 `76 01` 仍成功 |

> E1 会擦除整个 APP 区并写入测试数据，**会破坏当前 APP**，只允许在测试样件上执行。
> E10/E11 已包含在 E1 末尾（`31 FF02` / `31 FF01`），CAPL 不单独拆用例。

## 4. 失败排查指引

| 实际 NRC | 对应层次 | 常见原因 |
|---|---|---|
| `0x11` SNS | DCM 查表 | SID 未注册到 `Boot_Dcm_SvcTable` |
| `0x7F` SNSIAS | DCM 会话门 | 服务不在当前会话 `SessionMask` |
| `0x33` SAD | DCM 安全门 | `SecLevel` 对应等级未解锁 |
| `0x12/0x13` | 处理器 | 子功能/长度校验 |
| `0x24` RSE | 刷写状态机 | 顺序不对（未请求种子/未开始下载） |
| `0x31` ROOR | DID/参数 | 业务 DID 不在当前会话（默认读 F190 等）；或 DID/地址非法 |
| `0x22` CNC | 刷写 / DSC | 状态机未到允许状态；下载中 `10 03` |
| `0x35` IK | 0x27 | key 与 ~seed 不符 |
| `0x36` EAT | 0x27 | 连续 3 次错误 key（`BOOT_SA_MAX_ATTEMPTS`） |
| `0x37` RTDNE | 0x27 | `0x36` 之后 10 s 惩罚期内再请求（`BOOT_SA_DELAY_MS`） |
| 无应答 | 传输层或 suppress | 检查 CAN 接线/ID/波特率，或请求带 0x80 |

## 5. 自动执行

### 方式一：CANoe（推荐，主测试环境）

测试模块：[Boot_Dcm_CanoeTest.can](Boot_Dcm_CanoeTest.can)（CAPL，无需 DBC/CDD，自带 ISO-TP 单/多帧收发，用例与第 3 节 A/B/C/D/H/E/F/G 对应）。

1. 打开 CANoe 配置，确保一个 CAN 通道为 500 kbit/s 并连到 ECU；
2. Test Setup → 右键 → Insert Test Environment → Test Module (CAPL)，选择该文件；
3. 编译（F7）后运行，报告会自动生成；
4. 默认跑 A（含 A9–A16/A18，不含 A17）/B/C/D/**H**/G 组以及 F3；`gRunFlash=1` 跑 E 组（含 E18），`gRunReset=1` 跑 F1/F2/F4，`gRunStress=1` 跑 A17（1000 次会话切换）。
   本工程 `HandleDsc` 允许任意已支持会话互切（含默认直跳编程）。下载中 `10 03` 回 `0x22` CNC（不离开编程）；`10 01` 仍可中止。回默认（`10 01` / S3）会 `DidReset` 恢复 F180 并清其它 DID RAM。解锁按会话隔离，扩展↔编程不互相拷贝。

### 方式二：Python + python-can（无 CANoe 时替代）

```powershell
pip install python-can
python Boot_Dcm_UdsTest.py --interface pcan --channel PCAN_USBBUS1 --bitrate 500000
python Boot_Dcm_UdsTest.py --interface pcan --channel PCAN_USBBUS1 --group session --group security
# 破坏性全流程（会擦除 APP）：
python Boot_Dcm_UdsTest.py --flash-test
```
